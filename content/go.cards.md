# Go flashcards (for Java/Kotlin developers)
<!-- Language features up to Go 1.27 checked against go.dev / golang/go via Context7 -->

## Types & structs

Q: How does a Go struct compare to a Java class?
A: A struct is just data (fields); behaviour is attached via **methods** declared separately with a receiver. No constructors, no inheritance, no `this` keyword, no annotations. Visibility is per package, by capitalisation.
```go
type User struct {
    ID   int64
    Name string
}
func (u User) Greeting() string { return "hi " + u.Name }
```

Q: What replaces constructors in Go?
A: Plain factory functions named `NewX` by convention, often returning a pointer, plus usable **zero values** (a struct that works with `var x T` needs no constructor at all).
```go
func NewServer(addr string, opts ...Option) *Server {
    s := &Server{addr: addr, timeout: 5 * time.Second}
    for _, o := range opts { o(s) }
    return s
}
```

Q: What are zero values? Give examples.
A: Every variable is initialised: `0`, `""`, `false`, `nil` for pointers/slices/maps/channels/funcs/interfaces, and structs with all-zero fields. No `null`-vs-uninitialised distinction like Java.
Idiomatic: design types so the zero value is useful — `sync.Mutex`, `bytes.Buffer`, `strings.Builder` work without init.

Q: Exported vs unexported identifiers?
A: An identifier starting with an **uppercase** letter is exported (public outside the package); lowercase is package-private. Applies to types, functions, methods, fields, constants.
Also matters for `encoding/json`: unexported fields are ignored.

Q: `var` vs `:=` vs `const`?
A: `var x int` / `var x = 5` — anywhere, explicit or inferred type.
`x := 5` — short declaration, **only inside functions**, declares (at least one new var on the left).
`const` — compile-time constants; untyped constants have arbitrary precision. `iota` builds enums:
```go
type State int
const (
    Pending State = iota // 0
    Running              // 1
    Failed               // 2
)
```

Q: How do you get an enum with a String() representation?
A: Typed int constants with `iota` plus a `String()` method (implements `fmt.Stringer`), often generated by `stringer`. There are no sealed enums: any `State(42)` is valid, so `switch` with a `default`.

Q: Does Go have generics? Show a basic generic function and type.
A: Yes (since 1.18). Type parameters with constraints:
```go
func Map[T, U any](xs []T, f func(T) U) []U {
    out := make([]U, 0, len(xs))
    for _, x := range xs { out = append(out, f(x)) }
    return out
}

type Number interface { ~int | ~int64 | ~float64 }
func Sum[T Number](xs ...T) (s T) { for _, x := range xs { s += x }; return }

type Stack[T any] struct{ items []T }
func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }
```

Q: What do `any`, `comparable` and `~int` mean in constraints?
A: `any` = `interface{}` (anything). `comparable` = types supporting `==` (usable as map keys). `~int` = any type whose **underlying** type is int (e.g. `type Port int`). Union `A | B` is only allowed in constraints.

Q: What generics limitations should a Java dev know?
A: - No variance or wildcards (`? extends`), no specialisation, no overloading.
- Methods could not declare their own type parameters before Go 1.27 (1.27 allows it on method declarations; interface methods still can't be generic).
- Not erased like Java, but there's no `T.class`: use `reflect.TypeFor[T]()` if you really need it.
Idiom: prefer interfaces for behaviour; use generics for containers and algorithms.

Q: Type alias vs defined type?
A: `type Celsius float64` defines a **new** type (needs conversion, can have methods).
`type MyAlias = float64` is an **alias** — the same type, interchangeable, used for refactoring/migrations. Generic aliases are allowed since 1.24.

Q: What is the difference between `new(T)` and `&T{}`? What changed in 1.26?
A: Both allocate a zero `T` and return `*T`; `&T{...}` can set fields. Go 1.26 lets `new` take an expression: `new(42)` is an `*int` pointing to 42 — handy for optional pointer fields like `Replicas: new(int32(3))` in Kubernetes specs.

## Methods & interfaces

Q: Value receiver vs pointer receiver — how do you choose?
A: Pointer receiver `func (s *Server) Start()` when the method **mutates** the receiver, the struct is large, or it contains a mutex/must not be copied. Value receiver for small immutable values (`time.Time`).
Be consistent: if any method needs a pointer receiver, make all pointer receivers.

Q: Explain the "pointer receiver interface rule" (method sets).
A: The method set of `T` contains only value-receiver methods; the method set of `*T` contains both. So if `Write` has a pointer receiver, only `*T` implements `io.Writer`:
```go
type Buf struct{ b []byte }
func (x *Buf) Write(p []byte) (int, error) { x.b = append(x.b, p...); return len(p), nil }

var w io.Writer = &Buf{} // ok
var w2 io.Writer = Buf{}  // compile error: Write has pointer receiver
```

Q: How are interfaces implemented in Go vs Java?
A: **Implicitly** (structural typing): a type implements an interface by having the methods — no `implements` keyword. Interfaces are usually small and **defined by the consumer**, not the producer.
"Accept interfaces, return structs." Compile-time check idiom:
```go
var _ http.Handler = (*MyHandler)(nil)
```

Q: Why are Go interfaces typically tiny (io.Reader, io.Writer)?
A: Small interfaces (1–2 methods) are easy to implement, mock and compose (`io.ReadWriteCloser` = embedding). Because satisfaction is implicit, a consumer can define exactly the subset it needs, e.g. `type userGetter interface{ GetUser(ctx, id) (*User, error) }` for testing.

Q: What is the nil interface gotcha?
A: An interface value is (type, value). An interface holding a **typed nil pointer** is not `== nil`:
```go
func find() error {
    var e *MyErr = nil
    return e          // returns non-nil error interface!
}
```
Return a literal `nil` for "no error".

Q: Type assertion and type switch?
A: ```go
s, ok := v.(fmt.Stringer)     // ok=false instead of panic
switch x := v.(type) {
case int:    fmt.Println("int", x)
case string: fmt.Println("string", x)
case nil:    fmt.Println("nil")
default:     fmt.Printf("%T\n", x)
}
```
Similar to Kotlin `when (x) { is Int -> }` / Java pattern matching.

Q: Embedding vs inheritance?
A: Embedding a type promotes its fields and methods to the outer type — **composition with delegation sugar**, not inheritance. There's no polymorphic `super`, no overriding: the outer type can shadow a method, but the embedded type's code never calls the outer one.
```go
type Logger struct{}
func (Logger) Log(s string) {}
type Service struct {
    Logger          // svc.Log("x") works
    db *sql.DB
}
```

Q: How do you embed an interface in a struct and why?
A: Embedding an interface field lets you wrap/decorate and override only some methods; unimplemented ones delegate to the embedded value (and panic if it's nil). Common in tests: embed the interface, override the one method you need.
```go
type countingWriter struct {
    io.Writer
    n int
}
func (c *countingWriter) Write(p []byte) (int, error) { c.n += len(p); return c.Writer.Write(p) }
```

Q: What is the functional options pattern?
A: Variadic option functions to configure a struct without telescoping constructors or builders:
```go
type Option func(*Server)
func WithTimeout(d time.Duration) Option { return func(s *Server) { s.timeout = d } }

srv := NewServer(":8080", WithTimeout(10*time.Second))
```
Go's replacement for Kotlin default/named arguments and Java builders.

## Errors

Q: How does Go handle errors compared to Java exceptions?
A: Errors are **values**: functions return `(result, error)` and callers check `if err != nil` explicitly. No checked/unchecked exceptions, no try/catch. Control flow is visible; you add context as errors bubble up.
```go
f, err := os.Open(path)
if err != nil {
    return fmt.Errorf("open config %q: %w", path, err)
}
defer f.Close()
```

Q: What does `%w` do in fmt.Errorf?
A: Wraps the original error so it stays inspectable: `errors.Unwrap`, `errors.Is`, `errors.As` walk the chain. `%v` would only copy the text and lose the identity. Multiple `%w` are allowed (tree of errors), as is `errors.Join(e1, e2)`.

Q: errors.Is vs errors.As?
A: `errors.Is(err, target)` — is any error in the chain **equal** to a sentinel? (`errors.Is(err, fs.ErrNotExist)`)
`errors.As(err, &target)` — is any error in the chain of a **type**, and extract it:
```go
var nf *NotFoundError
if errors.As(err, &nf) { log.Println(nf.ID) }
// Go 1.26+: generic variant
if nf, ok := errors.AsType[*NotFoundError](err); ok { ... }
```

Q: Sentinel errors vs custom error types?
A: Sentinel: `var ErrNotFound = errors.New("not found")` — compare with `errors.Is`. Cheap, but no extra data.
Custom type: a struct implementing `Error() string` — carries data (ID, status code), matched with `errors.As`. Kubernetes uses helper predicates like `apierrors.IsNotFound(err)`.

Q: When is panic appropriate?
A: For truly unrecoverable programmer errors / impossible states (nil map write, index out of range, failed `regexp.MustCompile` at init). **Not** for expected failures like I/O or bad input — return an error. Libraries should almost never let panics escape.

Q: How do defer, panic and recover work?
A: `defer` schedules a call to run when the function returns (LIFO), even during a panic. `recover()` called **inside a deferred function** stops the panic and returns its value:
```go
func safe(f func()) (err error) {
    defer func() {
        if r := recover(); r != nil { err = fmt.Errorf("panic: %v", r) }
    }()
    f()
    return nil
}
```
HTTP servers do this per request. A panic in another goroutine can't be recovered here — it crashes the program.

Q: When are deferred call arguments evaluated? Name a defer gotcha.
A: Arguments are evaluated **when `defer` executes**, not at function exit: `defer fmt.Println(i)` prints the value at that moment.
Gotcha: `defer` in a loop runs only at function end → files stay open: wrap the loop body in a function. Also, ignoring `Close()` errors on writable files can hide data loss.

## Slices, arrays & maps

Q: Array vs slice?
A: Array `[4]int` — fixed size, part of the type, **value** (copied on assignment).
Slice `[]int` — a descriptor `{pointer, len, cap}` over a backing array; cheap to pass, shares data. Almost all Go code uses slices (≈ `ArrayList` view, but can alias).

Q: What do len and cap mean, and how does append grow a slice?
A: `len` = elements visible; `cap` = space in the backing array from the start of the slice. `append` writes in place if `len < cap`, otherwise allocates a bigger array (roughly doubling for small slices) and copies. **Always use the result**: `s = append(s, x)`.

Q: Classic append/aliasing gotcha?
A: Two slices sharing a backing array can overwrite each other:
```go
a := make([]int, 3, 10)
b := append(a, 1) // writes a[3] slot in shared array
c := append(a, 2) // overwrites the same slot!
fmt.Println(b[3]) // 2
```
Fix: full slice expression `a[:3:3]` (cap = len) or `slices.Clone`.

Q: Slicing a big slice can leak memory. Why?
A: `small := big[:10]` keeps the whole backing array alive. Copy what you need (`slices.Clone(big[:10])`) when holding on to a small part of a large buffer.

Q: nil slice vs empty slice?
A: `var s []int` (nil) and `s := []int{}` both have len 0 and work with `append`, `range`, `len`. Difference: `s == nil` and JSON encoding (`null` vs `[]`). Return nil slices idiomatically unless the JSON shape matters.

Q: How do maps behave in Go?
A: `m := map[string]int{}` or `make(map[string]int, hint)`. Reading a missing key returns the zero value; use comma-ok to distinguish:
```go
v, ok := m["k"]
delete(m, "k")
```
Iteration order is **randomised**. Writing to a nil map panics. Maps are **not safe for concurrent writes** (fatal error) — use a mutex or `sync.Map`.

Q: Can you take the address of a map element or modify a struct inside a map?
A: No: `m[k].Field = 1` doesn't compile, because map entries can move when the map grows. Store pointers (`map[string]*T`) or read-modify-write the value: `v := m[k]; v.Field = 1; m[k] = v`.

Q: What do the `slices` and `maps` packages give you?
A: Generic helpers (1.21+): `slices.Sort`, `slices.SortFunc`, `slices.Contains`, `slices.Index`, `slices.BinarySearch`, `slices.Compact`, `slices.Clone`, `slices.Equal`; `maps.Keys`/`maps.Values` (iterators since 1.23), `maps.Clone`. Combined with `slices.Collect(maps.Keys(m))` and `slices.Sorted(...)`.

Q: How does `for range` work and what changed in Go 1.22?
A: `for i, v := range slice`, `for k, v := range m`, `for v := range ch`, `for i := range 10` (1.22+ integers), and range-over-func iterators (1.23+).
Since 1.22 each iteration gets a **fresh loop variable**, fixing the classic bug where closures/goroutines captured the same variable. `v` is still a copy: modify via `s[i]`.

Q: What are range-over-func iterators?
A: Since 1.23, `range` accepts functions of type `iter.Seq[V]` = `func(yield func(V) bool)`:
```go
func Evens(n int) iter.Seq[int] {
    return func(yield func(int) bool) {
        for i := 0; i < n; i += 2 {
            if !yield(i) { return }
        }
    }
}
for v := range Evens(10) { fmt.Println(v) }
```
Like Kotlin sequences / Java streams but push-based; stop when `yield` returns false.

Q: Strings, bytes and runes?
A: A string is an immutable byte sequence (usually UTF-8). `len(s)` = bytes; `s[i]` = a byte; `for i, r := range s` iterates **runes** (Unicode code points). Build strings with `strings.Builder`; convert with `[]byte(s)` / `string(b)` (copies).

## Packages & modules

Q: Package vs module?
A: A **package** = a directory of `.go` files with the same `package` name; the unit of compilation and visibility.
A **module** = a versioned collection of packages with a `go.mod` (module path, Go version, dependencies) — like a Maven artifact. `go.sum` pins checksums.

Q: Essential go module commands?
A: ```bash
go mod init github.com/acme/svc
go get github.com/foo/bar@v1.4.0   # add/upgrade dep
go mod tidy                        # add missing, drop unused
go build ./... ; go test ./... ; go vet ./...
go run ./cmd/server
go work init ./a ./b               # multi-module workspace
```

Q: How does Go pick dependency versions?
A: **Minimal Version Selection**: for each module, use the highest of the minimum versions required by anyone — not the newest available. Deterministic, no lockfile solver. Major versions ≥2 change the import path (`/v2`).

Q: What is the `internal` directory rule?
A: Packages under `.../internal/...` can only be imported by code rooted at the parent of `internal`. Enforced by the compiler — Go's way to hide implementation packages (like Java module non-exported packages).

Q: What does `init()` do and why use it sparingly?
A: Each package may have `init()` functions run once after package variables are initialised, before `main`. Order follows imports. Hidden side effects make testing hard; prefer explicit setup. Common legit use: registering drivers/schemes (`_ "github.com/lib/pq"`).

Q: Typical Go project layout?
A: `cmd/<binary>/main.go` (thin mains), `internal/...` (app code), `pkg/...` (optional public libs), `api/` (types/CRDs), `go.mod` at root. Packages named by what they provide (`store`, `httpapi`), not `utils`. No circular imports allowed.

## Concurrency

Q: What is a goroutine and how is it different from a Java thread?
A: A function running concurrently, started with `go f()`. Managed by the Go runtime scheduler (M:N onto OS threads), starts with a ~2 KB growable stack — you can run hundreds of thousands. Closest JVM analogue: **virtual threads** (Loom) or Kotlin coroutines, but no structured concurrency built in.

Q: What is a channel? Unbuffered vs buffered?
A: A typed conduit between goroutines: `ch := make(chan int)`.
- **Unbuffered**: send blocks until a receiver takes it — a synchronisation point (rendezvous).
- **Buffered** `make(chan int, 10)`: send blocks only when the buffer is full; receive blocks when empty.
"Don't communicate by sharing memory; share memory by communicating."

Q: Rules for closing channels?
A: Only the **sender** closes, and only when receivers need to know "no more values". Receiving from a closed channel returns the zero value immediately (`v, ok := <-ch` → `ok=false`); `range ch` ends. Sending on a closed channel or closing twice **panics**. Nil channels block forever (useful to disable a `select` case).

Q: What does `select` do?
A: Waits on multiple channel operations and runs whichever is ready first (random if several). `default` makes it non-blocking.
```go
select {
case msg := <-in:
    handle(msg)
case <-ctx.Done():
    return ctx.Err()
case <-time.After(2 * time.Second):
    return errTimeout
}
```

Q: Directional channel types?
A: `chan<- T` send-only, `<-chan T` receive-only. Used in signatures to document and enforce ownership: a producer returns `<-chan T`, a consumer takes `<-chan T`.

Q: How does sync.WaitGroup work? What's new in 1.25?
A: Counts outstanding goroutines: `Add(n)` before starting, `Done()` in each, `Wait()` blocks until zero (≈ `CountDownLatch`). Go 1.25 added `wg.Go(f)` which does Add/Done for you:
```go
var wg sync.WaitGroup
for _, u := range urls {
    wg.Go(func() { fetch(u) })
}
wg.Wait()
```

Q: What does errgroup add over WaitGroup?
A: `golang.org/x/sync/errgroup`: returns the **first error**, cancels a shared context on failure, and limits concurrency:
```go
g, ctx := errgroup.WithContext(ctx)
g.SetLimit(8)
for _, id := range ids {
    g.Go(func() error { return process(ctx, id) })
}
if err := g.Wait(); err != nil { return err }
```
Closest thing to structured concurrency in Go.

Q: sync.Mutex vs sync.RWMutex?
A: `Mutex` — exclusive lock (`Lock`/`Unlock`, usually `defer mu.Unlock()`). Not reentrant (unlike Java `synchronized`/ReentrantLock) — locking twice in one goroutine deadlocks.
`RWMutex` — many readers or one writer; only worth it for read-heavy workloads. Never copy a struct containing a mutex (`go vet` catches it).

Q: When to use sync/atomic, sync.Once, sync.Map, sync.Pool?
A: - `atomic.Int64`, `atomic.Bool`, `atomic.Pointer[T]` — lock-free counters/flags.
- `sync.Once` / `sync.OnceValue` — lazy, thread-safe initialisation.
- `sync.Map` — concurrent map for append-mostly or disjoint-key workloads; otherwise map+mutex.
- `sync.Pool` — reuse temporary objects (buffers) to cut GC pressure.

Q: What is context.Context for?
A: Carries **cancellation**, **deadlines** and request-scoped values across API boundaries and goroutines. First parameter by convention: `func Do(ctx context.Context, ...)`. When a parent is cancelled, all derived contexts are cancelled. Every blocking I/O call in modern Go takes a ctx.

Q: How do you create contexts with timeouts and cancellation?
A: ```go
ctx, cancel := context.WithTimeout(parent, 3*time.Second)
defer cancel() // always: releases timers/resources
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)

ctx, cancel := context.WithCancelCause(parent)
cancel(errShutdown) // context.Cause(ctx) == errShutdown
```
Check `ctx.Err()` (`context.Canceled` / `context.DeadlineExceeded`) or `<-ctx.Done()` in loops.

Q: Context dos and don'ts?
A: Do: pass it explicitly as the first arg; derive child contexts; respect `Done()` in long loops.
Don't: store it in structs; pass `nil` (use `context.TODO()`); use `WithValue` for optional parameters — only request-scoped data (trace ID, auth), with unexported key types.

Q: What causes a goroutine leak? How do you prevent it?
A: A goroutine blocked forever: sending to a channel nobody reads, receiving from a channel nobody closes, waiting without a ctx. Leaks grow memory and goroutine counts.
Prevent: every goroutine needs a clear exit (ctx cancellation, closed channel), use buffered channels of size 1 for "maybe-abandoned" results, and test with `goleak`.

Q: What is a data race and how do you find it?
A: Two goroutines access the same memory concurrently, at least one writing, without synchronisation — undefined behaviour (torn reads, map corruption). Detect with the race detector:
```bash
go test -race ./...
go run -race .
```
Fix with channels, mutexes or atomics.

Q: Common Go concurrency bugs?
A: - Data races on maps/slices/counters.
- Goroutine leaks (blocked send/receive, no ctx).
- Deadlocks: unbuffered send with no receiver, lock ordering, `wg.Wait()` before `Add`.
- Closing a channel twice / from the receiver side.
- Copying a `sync.Mutex` or `WaitGroup` by value.
- Forgetting `cancel()`; `time.After` in hot loops (allocates timers).

Q: Fan-out / fan-in pipeline pattern?
A: Fan-out: several workers read from the same input channel. Fan-in: merge results into one channel, close it when all workers finish:
```go
out := make(chan Result)
var wg sync.WaitGroup
for range n {
    wg.Go(func() { for j := range jobs { out <- do(j) } })
}
go func() { wg.Wait(); close(out) }()
for r := range out { ... }
```

Q: How do you rate-limit or bound concurrency simply?
A: A buffered channel as a **semaphore**:
```go
sem := make(chan struct{}, 10)
for _, j := range jobs {
    sem <- struct{}{}
    go func() { defer func() { <-sem }(); work(j) }()
}
```
Or `errgroup.SetLimit`, `golang.org/x/sync/semaphore`, and `golang.org/x/time/rate` for token buckets.

Q: What is GOMAXPROCS and what changed in Go 1.25?
A: The number of OS threads executing Go code simultaneously (default = CPUs). Since 1.25 the runtime respects **cgroup CPU limits** on Linux and updates GOMAXPROCS dynamically — important in Kubernetes, where a Pod limited to 2 CPUs on a 64-core node used to get 64 and suffer throttling.

Q: What is GOMEMLIMIT?
A: A soft memory limit for the Go runtime (since 1.19): the GC works harder as the heap approaches it. Set it to ~90% of the container memory limit to avoid OOMKills: `GOMEMLIMIT=900MiB`. Analogous to JVM `-Xmx`/`MaxRAMPercentage`, but soft.

## Testing & tooling

Q: How does testing work in Go?
A: Files `*_test.go`, functions `func TestXxx(t *testing.T)`, run by `go test ./...`. No assertion library in stdlib: `t.Errorf` (continue) / `t.Fatalf` (stop). Subtests with `t.Run`, helpers marked with `t.Helper()`, cleanup with `t.Cleanup`, parallel with `t.Parallel()`.

Q: Show a table-driven test.
A: ```go
func TestParsePort(t *testing.T) {
    tests := []struct {
        name    string
        in      string
        want    int
        wantErr bool
    }{
        {"valid", "8080", 8080, false},
        {"not a number", "http", 0, true},
        {"out of range", "70000", 0, true},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got, err := ParsePort(tt.in)
            if (err != nil) != tt.wantErr {
                t.Fatalf("err = %v, wantErr %v", err, tt.wantErr)
            }
            if got != tt.want {
                t.Errorf("got %d, want %d", got, tt.want)
            }
        })
    }
}
```

Q: How do you mock dependencies in Go tests?
A: Define a small interface at the consumer, inject it, and pass a hand-written fake in tests (no Mockito needed). For HTTP use `httptest.NewServer`/`httptest.NewRecorder`; for Kubernetes controllers the controller-runtime fake client or envtest; for time `testing/synctest` (1.25) to run code with a fake clock.

Q: Benchmarks and fuzzing?
A: ```go
func BenchmarkEncode(b *testing.B) {
    for b.Loop() { encode(data) }     // Go 1.24+ (was: for i := 0; i < b.N; i++)
}
func FuzzParse(f *testing.F) {
    f.Add("8080")
    f.Fuzz(func(t *testing.T, s string) { ParsePort(s) })
}
```
`go test -bench=. -benchmem`, `go test -fuzz=FuzzParse`.

Q: Essential Go tooling?
A: `gofmt`/`goimports` (one canonical format), `go vet` (suspicious code), `staticcheck`/`golangci-lint`, `go test -race -cover`, `pprof` (`net/http/pprof`, `go tool pprof`), `go build -ldflags "-X main.version=1.2.3"`, `dlv` debugger, `govulncheck`.

Q: How do you profile a Go service in production?
A: Import `net/http/pprof` on an internal port, then:
```bash
go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30   # CPU
go tool pprof http://localhost:6060/debug/pprof/heap
curl localhost:6060/debug/pprof/goroutine?debug=2                   # all stacks
```
The goroutine dump is the first thing to check for leaks or deadlocks.

## HTTP & JSON

Q: Minimal net/http server with method/path routing?
A: Since 1.22, `ServeMux` patterns support methods and wildcards:
```go
mux := http.NewServeMux()
mux.HandleFunc("GET /users/{id}", func(w http.ResponseWriter, r *http.Request) {
    id := r.PathValue("id")
    fmt.Fprintf(w, "user %s", id)
})
srv := &http.Server{Addr: ":8080", Handler: mux, ReadHeaderTimeout: 5 * time.Second}
log.Fatal(srv.ListenAndServe())
```

Q: What is an http.Handler and how do middlewares work?
A: `type Handler interface { ServeHTTP(ResponseWriter, *Request) }`; `http.HandlerFunc` adapts a function. Middleware = a function wrapping a handler:
```go
func logging(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        next.ServeHTTP(w, r)
        slog.Info("req", "method", r.Method, "path", r.URL.Path, "dur", time.Since(start))
    })
}
```
Each request runs in its own goroutine.

Q: How do you shut down an HTTP server gracefully (Kubernetes SIGTERM)?
A: ```go
ctx, stop := signal.NotifyContext(context.Background(), syscall.SIGTERM, os.Interrupt)
defer stop()
go func() {
    if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
        log.Fatal(err)
    }
}()
<-ctx.Done()
shutdownCtx, cancel := context.WithTimeout(context.Background(), 20*time.Second)
defer cancel()
srv.Shutdown(shutdownCtx) // stop accepting, drain in-flight requests
```

Q: Why should you never use http.Get / the default client in production code?
A: `http.DefaultClient` has **no timeout** — a hung server blocks forever. Create a client with `Timeout`, reuse it (connection pooling), pass ctx via `NewRequestWithContext`, always `defer resp.Body.Close()` and drain the body to reuse connections.

Q: How do struct tags and encoding/json work?
A: ```go
type User struct {
    ID      int64     `json:"id"`
    Email   string    `json:"email,omitempty"`
    Created time.Time `json:"created_at"`
    pass    string    // unexported: never serialised
    Secret  string    `json:"-"`
}
b, err := json.Marshal(u)
err = json.Unmarshal(b, &u)
```
Tags are metadata read via reflection — similar role to Jackson annotations. `omitzero` (1.24+) omits zero structs like `time.Time{}`.

Q: Decoding JSON request bodies safely?
A: ```go
r.Body = http.MaxBytesReader(w, r.Body, 1<<20)
dec := json.NewDecoder(r.Body)
dec.DisallowUnknownFields()
var in CreateReq
if err := dec.Decode(&in); err != nil {
    http.Error(w, "bad json: "+err.Error(), http.StatusBadRequest)
    return
}
```
Unknown JSON fields are silently ignored by default; numbers into `any` become `float64` (use `dec.UseNumber()`).

Q: What is log/slog?
A: The structured logging package (1.21+): `slog.Info("msg", "key", val)`, JSON or text handlers, `slog.With(...)` for context, levels. Replaces most uses of logrus/zap in new code; Kubernetes components use klog/logr which can bridge to slog.

## Gotchas & idioms

Q: Name five Go gotchas that bite Java/Kotlin developers.
A: - Typed nil in an interface is not nil.
- `append` may or may not alias the original slice.
- Map iteration order is random; concurrent map writes crash.
- `for _, v := range` gives copies of elements.
- No overloading, no default args, no ternary operator; unused imports/vars are compile errors.
- Integer division and overflow wrap silently; no implicit numeric conversion.

Q: Why does Go have no exceptions, no inheritance and few features?
A: Deliberate simplicity for large teams: explicit control flow, composition over inheritance, one way to format code, fast compilation, easy reading of unfamiliar code. The trade-off is verbosity (`if err != nil`) for clarity.

Q: How do Go and the JVM differ at runtime for cloud services?
A: Go compiles to a single static native binary: fast startup (ms), small memory footprint, tiny distroless images, no JIT warm-up — ideal for CLIs, operators and sidecars. GC is concurrent and low-latency but non-generational (Green Tea GC is default since 1.26), with fewer tuning knobs (`GOGC`, `GOMEMLIMIT`).

Q: How do you return multiple values and use named results?
A: ```go
func divmod(a, b int) (q, r int) {
    q = a / b
    r = a % b
    return // "naked" return of named results
}
q, _ := divmod(7, 2) // blank identifier discards
```
Named results also let a deferred function modify the returned error.

Q: What are closures and function types in Go?
A: Functions are first-class values; closures capture variables **by reference**:
```go
func counter() func() int {
    n := 0
    return func() int { n++; return n }
}
type HandlerFunc func(http.ResponseWriter, *http.Request)
```
Functions types can have methods (`HandlerFunc.ServeHTTP`) — an adapter trick used across the stdlib.

Q: Explain `switch` in Go vs Java.
A: No fall-through by default (use `fallthrough` explicitly), cases can be expressions or lists (`case 'a', 'e':`), and a tag-less `switch { case x > 10: ... }` replaces if-else chains. Works on any comparable type, including strings.

## Practice: write it by hand

Q: ✍️ Write a thread-safe counter with Inc and Value, then the same with atomics.
A: ```go
type Counter struct {
    mu sync.Mutex
    n  map[string]int
}

func (c *Counter) Inc(key string) {
    c.mu.Lock()
    defer c.mu.Unlock()
    if c.n == nil {
        c.n = make(map[string]int)
    }
    c.n[key]++
}

func (c *Counter) Value(key string) int {
    c.mu.Lock()
    defer c.mu.Unlock()
    return c.n[key]
}

// single counter, lock-free
type Hits struct{ n atomic.Int64 }

func (h *Hits) Inc() int64 { return h.n.Add(1) }
```
Pointer receivers (mutex must not be copied); zero value usable.

Q: ✍️ Write a worker pool: N workers process jobs from a channel and send results back; stop on context cancellation.
A: ```go
func Pool(ctx context.Context, workers int, jobs <-chan int) <-chan int {
    results := make(chan int)
    var wg sync.WaitGroup
    for range workers {
        wg.Add(1)
        go func() {
            defer wg.Done()
            for {
                select {
                case <-ctx.Done():
                    return
                case j, ok := <-jobs:
                    if !ok {
                        return
                    }
                    select {
                    case results <- j * j:
                    case <-ctx.Done():
                        return
                    }
                }
            }
        }()
    }
    go func() { wg.Wait(); close(results) }()
    return results
}
```
Key points: the pool closes `results` only after all workers exit; every blocking op also selects on `ctx.Done()`.

Q: ✍️ Write an HTTP JSON handler: POST /users decodes a body, validates, stores it, returns 201 with JSON.
A: ```go
type CreateUser struct {
    Name  string `json:"name"`
    Email string `json:"email"`
}
type User struct {
    ID    int64  `json:"id"`
    Name  string `json:"name"`
    Email string `json:"email"`
}

type API struct {
    mu     sync.Mutex
    nextID int64
    users  map[int64]User
}

func (a *API) createUser(w http.ResponseWriter, r *http.Request) {
    var in CreateUser
    dec := json.NewDecoder(http.MaxBytesReader(w, r.Body, 1<<20))
    dec.DisallowUnknownFields()
    if err := dec.Decode(&in); err != nil {
        writeJSON(w, http.StatusBadRequest, map[string]string{"error": err.Error()})
        return
    }
    if in.Name == "" || !strings.Contains(in.Email, "@") {
        writeJSON(w, http.StatusUnprocessableEntity, map[string]string{"error": "invalid user"})
        return
    }
    a.mu.Lock()
    a.nextID++
    u := User{ID: a.nextID, Name: in.Name, Email: in.Email}
    a.users[u.ID] = u
    a.mu.Unlock()
    writeJSON(w, http.StatusCreated, u)
}

func writeJSON(w http.ResponseWriter, status int, v any) {
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(status)
    json.NewEncoder(w).Encode(v)
}

// mux.HandleFunc("POST /users", api.createUser)
```
Headers must be set **before** `WriteHeader`.

Q: ✍️ Fetch N URLs concurrently with a concurrency limit of 5 and an overall timeout; return the first error.
A: ```go
func FetchAll(ctx context.Context, urls []string) ([]int, error) {
    ctx, cancel := context.WithTimeout(ctx, 10*time.Second)
    defer cancel()

    sizes := make([]int, len(urls)) // each goroutine writes its own index: no race
    g, ctx := errgroup.WithContext(ctx)
    g.SetLimit(5)
    for i, u := range urls {
        g.Go(func() error {
            req, err := http.NewRequestWithContext(ctx, http.MethodGet, u, nil)
            if err != nil {
                return err
            }
            resp, err := http.DefaultClient.Do(req) // ctx bounds the time
            if err != nil {
                return fmt.Errorf("get %s: %w", u, err)
            }
            defer resp.Body.Close()
            b, err := io.ReadAll(resp.Body)
            if err != nil {
                return err
            }
            sizes[i] = len(b)
            return nil
        })
    }
    return sizes, g.Wait()
}
```

Q: ✍️ Implement a TTL cache safe for concurrent use (generic).
A: ```go
type entry[V any] struct {
    val V
    exp time.Time
}

type Cache[K comparable, V any] struct {
    mu   sync.RWMutex
    ttl  time.Duration
    data map[K]entry[V]
}

func NewCache[K comparable, V any](ttl time.Duration) *Cache[K, V] {
    return &Cache[K, V]{ttl: ttl, data: make(map[K]entry[V])}
}

func (c *Cache[K, V]) Set(k K, v V) {
    c.mu.Lock()
    defer c.mu.Unlock()
    c.data[k] = entry[V]{v, time.Now().Add(c.ttl)}
}

func (c *Cache[K, V]) Get(k K) (V, bool) {
    c.mu.RLock()
    defer c.mu.RUnlock()
    e, ok := c.data[k]
    if !ok || time.Now().After(e.exp) {
        var zero V
        return zero, false
    }
    return e.val, true
}
```
Follow-ups: background janitor goroutine stopped via ctx, LRU bound, `singleflight` to avoid thundering herd.

Q: ✍️ Write a retry helper with exponential backoff that respects context.
A: ```go
func Retry(ctx context.Context, attempts int, base time.Duration, f func(context.Context) error) error {
    var err error
    for i := range attempts {
        if err = f(ctx); err == nil {
            return nil
        }
        delay := base << i // base, 2*base, 4*base...
        t := time.NewTimer(delay)
        select {
        case <-ctx.Done():
            t.Stop()
            return errors.Join(err, ctx.Err())
        case <-t.C:
        }
    }
    return fmt.Errorf("after %d attempts: %w", attempts, err)
}
```
In production add jitter and only retry retryable errors.

Q: ✍️ Write a mini reconcile loop: keep the number of running "replicas" equal to desired, triggered by events and a periodic resync.
A: ```go
type Reconciler struct {
    mu      sync.Mutex
    desired int
    running map[string]bool
}

func (r *Reconciler) reconcile() {
    r.mu.Lock()
    defer r.mu.Unlock()
    for len(r.running) < r.desired { // scale up
        r.running[fmt.Sprintf("replica-%d", rand.Int())] = true
    }
    for name := range r.running { // scale down (deleting during range is safe)
        if len(r.running) <= r.desired {
            break
        }
        delete(r.running, name)
    }
}

func (r *Reconciler) Run(ctx context.Context, events <-chan struct{}) {
    resync := time.NewTicker(30 * time.Second)
    defer resync.Stop()
    for {
        r.reconcile() // level-triggered: always recompute from state
        select {
        case <-ctx.Done():
            return
        case <-events:
        case <-resync.C:
        }
    }
}
```
Talking points: idempotent, event content ignored, resync heals missed events.

Q: ✍️ Implement a graceful-shutdown main for an HTTP service with a /healthz endpoint.
A: ```go
func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /healthz", func(w http.ResponseWriter, r *http.Request) {
        w.WriteHeader(http.StatusOK)
    })
    srv := &http.Server{Addr: ":8080", Handler: mux, ReadHeaderTimeout: 5 * time.Second}

    ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
    defer stop()

    errCh := make(chan error, 1)
    go func() { errCh <- srv.ListenAndServe() }()

    select {
    case err := <-errCh:
        log.Fatalf("server: %v", err)
    case <-ctx.Done():
    }
    shutdownCtx, cancel := context.WithTimeout(context.Background(), 20*time.Second)
    defer cancel()
    if err := srv.Shutdown(shutdownCtx); err != nil {
        log.Printf("shutdown: %v", err)
    }
}
```
`errCh` is buffered so the goroutine never leaks when nobody reads it.

Q: ✍️ Write a generic Filter and a function that groups strings by length (returning sorted keys).
A: ```go
func Filter[T any](xs []T, keep func(T) bool) []T {
    var out []T
    for _, x := range xs {
        if keep(x) {
            out = append(out, x)
        }
    }
    return out
}

func GroupByLen(words []string) (map[int][]string, []int) {
    groups := make(map[int][]string)
    for _, w := range words {
        groups[len(w)] = append(groups[len(w)], w) // nil slice append is fine
    }
    keys := slices.Sorted(maps.Keys(groups))
    return groups, keys
}
```
